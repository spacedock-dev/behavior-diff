Refactoring plan · no production code changed

Keep the workshop.
Give each job a clear home.

We do not need to rebuild Behavior Diff. Keep the working trial runner and report renderer. Untangle how evidence is observed, assessed, and handed between stages.

Based on the agreed illustrated design and the current source. New module and artifact names below are proposed, not existing APIs.

The main change

Today / one crowded desk

One call sees everything

decisions.py combines trial evidence, the edit, goals, assessment, and narrative. The host then separately audits the result.

Fewer model calls, but observation and goal-based interpretation share the same context.

Target / separate labeled results

Observe first. Assess second.

The observer describes behavior without a separately supplied edit or goal sheet. The assessor checks goals against those observations and original evidence.

Separate contexts and explicit payloads—not an instruction to “ignore” information already supplied.

Recommended order: contracts → mechanical migration → semantic split → one report → full cutover.

Keep trial behavior stable while changing the analysis. Do not combine this with a report redesign, model-default change, or trial-count reduction.

Contracts tightened by independent review

These are implementation requirements for the phases below—not claims that the safeguards already exist.

Evidence: one inventory, two permitted views

Keep the immutable raw inventory local, with stable source IDs and byte locations. Build the observer view with deterministic selection that does not use goals, diff, private criteria, or source_requirements. Build the assessor view with the existing requirement-priority selection. Both views apply the existing privacy filters and size limits before model invocation. Record omissions, selection policy, and captured instruction-read exposure. “Original evidence” in a model payload means permitted recorded excerpts with original-source citations, never unrestricted audit output.

Unfiltered audit_evidence.py pages remain local. Sending more content to any provider requires specific consent; changing modules does not expand existing consent. Check that changing only goal requirements leaves observer selection unchanged, while assessor prioritization still works.

Observer: isolate the process, not only the prompt

Launch in a fresh empty temporary working directory outside the project and run directories. Disable file/tools access and automatic project/user instruction, settings, and MCP loading. Verify the effective invocation for every supported host before enabling it. If a host cannot enforce this boundary, fail the observer stage closed and show the limitation; do not silently weaken isolation. Before shipping the cutover, both Claude Code and Codex must pass the isolation check. If either cannot, stop for a user decision rather than shipping reduced assessment support on that host. An instruction read already present in permitted trial evidence is a disclosed limitation, not permission to read additional files.

Deterministic host-stub checks cover arguments, cwd, relevant environment/configuration, and attempted access to sentinel project/run files. Approved real-host checks are still required before claiming enforcement. Preserve existing provider fallback only where it meets the same stage boundary and records the actual host/model; no new fallback is introduced.

Partial results: a failed trial is not a broken pipeline

Every dependency declares required or optional input and receives an explicit terminal status when output is absent. The trial collection stage completes after all worker outcomes have been recorded, including failed or interrupted trials; a harness-level failure is different. Preserve the existing minimum of one complete trial per side for analysis and disclose unequal samples. Insufficient evidence skips observation; a failed required observer blocks assessment.

Rendering requires run metadata and an evidence inventory, which may be empty, but observation and assessment are optional inputs. It must produce an evidence/status-only report after analysis failure. Verify one failed trial, no usable trials on one side, observer failure, and assessor failure without inventing a verdict.

Status: one view does not mean one shared writable file

Preserve one writer per record: coordinator owns its record, each trial worker its own, and each analysis stage its own. Aggregate these into one logical status view when reading. Concurrent updates must not overwrite another producer’s progress; no new shared-file locking is needed.

Corrections: keep the first account and show what changed

Completed observations and assessments are write-once; the coordinator refuses an overwrite. A failed stage can be explicitly rerun only when no completed output exists; this is not an automatic retry policy. Add a bundled local revision command accepting parent artifact hash, author, reason, evidence references, and the changed assessment fields, including narrative. Revisions are append-only. Reject a stale parent or invalid citation.

The host still audits every private case locally and records its attributed findings in this assessment history. Keep private notes and raw audit material local; only permitted sanitized findings enter exported reports, and nothing is automatically sent back to a model provider. Render the latest revision with a visible correction label and access to the original account; preserve disagreements instead of silently overwriting the model. Update the skill’s old “never edit” rule to allow this explicit revision path, never hand-editing report files. Verify the correction in HTML, Markdown, and JSON without another model call.

Old reports and previews: preserve data, not the obsolete command

Retain read-only support for historical combined decisions.json runs under a clearly labeled “legacy combined analysis” schema branch. Do not fabricate observations or rerun extraction. Migrate the saved three-case report-preview workflow to this reader and the shipped renderer, removing its old --ingest invocation. Existing raw evidence and saved reports stay unchanged. This preserves historical rerendering without an executable compatibility alias or paid reanalysis.

The implementation sequence

Every phase below is planned, not completed. Intermediate work should remain on the refactoring branch until the coherent cutover is verified.

1 / Define the folders before moving the tools

Establish the stage and artifact contracts

A stage names what it needs, what it produces, and how it runs. The coordinator checks dependencies instead of assuming a fixed step number.

Concrete implementation
  • Proposed pipeline.py: stage registry, dependency validation, execution, and stage-result persistence. Keep this small; no workflow DSL or dynamic plugins.
  • Proposed stage_contract.py: artifact identity/version, producer implementation identity, input hashes, output references, and stage statuses.
  • Preparation enters as a validated external artifact from the host. The coordinator does not synthesize a missing plan.
  • Reject unknown dependencies, duplicate output ownership, and cycles before launching work. Reuse existing schemas rather than creating parallel definitions.
  • Persist completed/failed/skipped/blocked separately from goal outcomes. Failed required inputs block dependent stages; independent work may continue.

Acceptance: exercise the coordinator with existing deterministic validation operations and reject invalid dependency graphs before effects. After phase 3 supplies real trial and observation handlers, demonstrate registration of an evidence-index operation without editing those handlers. This is a one-off extension proof, not a new permanent coverage feature.

2 / Connect the working tools

Put existing mechanics behind the contract

Move ordering and ownership, not experimental meaning. Keep the same snapshots, task, model choices, isolation, and number of trials.

Concrete implementation
  • Extract the existing launch/collection operation into an invocable trial handler. Preserve run-trial.sh host normalization and concurrent workers.
  • Have the Bash front door pass the verified experiment to the coordinator. Do not leave a second hidden stage sequence in Bash.
  • Build the evidence index once from saved traces and original artifacts. Record interruptions and missing returns.
  • Migrate progress/status consumers to the stage result contract in the same change. Report availability must still require successful rendering.
  • Record the actual local or installed implementation selected for the run. Both variants use that identical implementation.

Acceptance: run the shipped orchestration through the existing deterministic host-stub harness; check snapshot isolation, trial concurrency, captured returns, interruption handling, and status output. No claim of live host behavior from these checks.

3 / Separate looking from judging

Split the combined extraction call

The observer gets evidence. The assessor gets the goals and evidence. Each runs in a fresh context and writes its own result.

Concrete implementation
  • Proposed observation.py: explicit observer payload, prompt, response validation, and immutable observations with original evidence references.
  • Proposed assessment.py: frozen checks, instruction diff, observations, and original evidence; goal outcomes, edit links, explanation, and limitations.
  • Proposed model_call.py: shared host/model invocation and exact model identity. Keep stage-specific payload selection out of this module.
  • Do not inherit the preparation conversation or let the observer read the run directory. Use restricted input payloads and verify each supported host's actual context/tool behavior.
  • Do not strip real instruction reads from captured evidence to claim blindness. Record this exposure as a limitation.
  • The assessor may identify an omitted or disputed observation with original citations, but cannot mutate the observer artifact.
  • Preserve the existing explicitly labeled diff-inferred goal/criteria fallback in the assessor when purpose or scenario is absent. Never present inferred criteria as frozen pre-trial checks, and never pass them to the observer. An observer failure blocks dependent assessment; the report still exposes retained raw evidence and failure status.

Acceptance: synthetic sentinel checks prove that explicit goals, private notes, and diff fields do not enter observer payloads. Separate approved live evaluation is required to measure semantic quality, host isolation, cost, and latency. Two calls are not automatically faster or more accurate.

4 / Print from one saved account

Connect separated artifacts to reporting

Keep the report and chat explanation aligned. Preserve observations even if an assessment is rejected or disputed.

Concrete implementation
  • Proposed new run outputs: observations.json, assessment.json, and a versioned stage-result record, alongside existing raw evidence.
  • Update report loading/schema and criterion validation together. Bump the report schema when the persisted contract changes.
  • Keep report narrative in the assessment result; deterministic rendering does not perform a third semantic pass. The host still audits every private case locally for reached/missed/unknown and supported/contradicted/insufficient outcomes; persist sanitized findings and disagreements as attributed revisions, not a competing unsaved verdict.
  • Record evidence-backed assessment corrections as explicit revisions with parent/input identities. Retain the original result.
  • For historical runs, never fabricate observer output from old combined decisions.json. Preserve their original reports and clearly identify legacy combined analysis when reading old evidence.
  • Keep historical data support distinct from a deprecated executable alias. New runs use the new contract only.

Acceptance: rerender saved artifacts with model execution unavailable; preserve observations when assessment fails; show incomplete coverage and legacy provenance honestly. Exercise HTML, Markdown, and structured JSON. Any presentation redesign needs the repository's separate preview gate.

5 / Switch every caller together

Finish the cutover, then remove obsolete code

A moved file is not a completed refactor. Callers, tests, docs, and status readers must all use the same contract.

Concrete implementation
  • Migrate the Bash launch, direct extraction invocations, fixture ingestion, human-evaluation tooling, preview-behavior-diff-summary, behavior-diff-retro, references/spacedock-duo.md, docs/skill-history-replay/README.md, README rerender guidance, CI checks, and documentation. Inspect the dogfood Action consumer and its extra model cost before cutover. Search all call sites before deleting decisions.py.
  • Replace tests tied to old internal functions with tests of evidence membership, payload isolation, partial failure, and report behavior. Do not preserve implementation-shape assertions.
  • Update docs/architecture.md and its flowchart, skill references, and release-note guidance in the same permanent change.
  • Run the required Bash/Python formatting checks and full deterministic suite. Keep model-backed evaluation out of normal CI and require explicit cost approval.
  • Complete independent review before any PR. Commit, push, PR, merge, and release remain separate authorization steps.

Acceptance: no active caller depends on the obsolete combined contract; a full comparison smoke reaches the new report, and saved evidence can rerender without inference. Report deterministic and approved live evidence separately.

One cutover constraint we must not hide

Live mode still calls the old extractor.

behavior-diff-live/SKILL.md currently calls decisions.py --emit-prompt and --ingest. Removing that interface while leaving the skill untouched would break it.

Recommendation: align the full extraction cutover with retirement of live mode, which requires separate explicit approval. This is a release gate, not permission to remove it now. Until then, keep the released path intact; do not ship a broken skill or build a permanent forwarding alias.

Retirement is an agreed future direction, not an action performed by this plan. Existing live reports remain evidence and must not be deleted.

What deliberately stays out

No new model defaults, reduced trial counts, report redesign, automatic retries, new provider fallbacks, caching system, distributed scheduler, or user-facing pipeline configuration. Extensibility means a small stable interface—not a new platform.
